# 从剧本到发布

目标：先完成一条角色相对稳定、声音清晰、剧情可理解的短样片，再依据实际工时决定是否扩大产量。当前系统完成制作准备阶段，下面区分程序已实现和人工操作。

## 1. 剧本：把故事写清楚

人工确定故事、主角目标、阻碍、转折和结尾悬念。先用少量角色、场景和镜头试做；示例是一集 30 秒的架空剧情。写好台词和画面后录入 JSON；现阶段不接受未拆镜的小说全文，也不自动推断人物。

运行 `validate` 检查字段、ID、人物引用和时长。内容质量、历史真实性、授权状态由人审核。

验收：每镜头知道“谁在什么地方做什么”，台词可直接朗读。

## 2. 分镜：变成制作指令

运行 `build`，按 `storyboard.md` 通读。每镜头保留清楚的主要动作，检查景别变化和前后衔接。看不明白的镜头应修改源 JSON 后重新生成到新目录。

验收：画面、角色、声音、预计时长都有记录，时间首尾连续。计划不证明生成素材能在该时长内完成动作。

## 3. 角色设定：先固定，再批量

检查 `characters.md`，锁定脸型、发型、衣服、配色、标志性细节和声音方向。先制作参考图，人工确认再生成正式镜头。文字描述只能减少遗漏，不能保证跨图一致；参考图控制、种子和模型能力需要单独验证。

验收：角色固定参考已批准；跑脸、换装等问题能对照纠正。

## 4. 图片生成：先跑通单镜头

当前把 `image_prompts.json` 中的提示词复制到图片工具。先做最难镜头，核对画幅、构图和角色，再批量制作。多角色镜头需要额外检查混脸和衣服互换。

按计划把图片放在生产包的 `images/shot_s001.png` 等位置，目录人工创建。当前程序不检查图片是否存在，也不会把 `pending` 自动改成完成。

验收：每镜头有批准图片或明确返工记录；记录生成次数和费用。

## 5. 配音：先听，再对齐

使用 `voice_lines.csv` 制作配音。先试听每个角色；确认声音可用于计划中的用途。按 `audio/shot_s001_line_01.wav` 等约定整理音频。

SRT 把镜头时间按台词字数分给各句，没有学习语速、停顿或情绪，也没有做语音识别。**不能把估时结果当成精确字幕。** 必须按真实配音调整镜头和字幕。无台词镜头不生成字幕，也不挤掉后续静音时间。

验收：声音清晰、读音正确，台词不截断，字幕与真实音频同步。

## 6. 剪辑：完成样片

在剪映等工具中导入图片和音频，按分镜排序，加入适度推拉、音效、音乐和字幕。需要人物动作的镜头可以后续单独验证图生视频工具。

SRT 导入入口及兼容情况以当前剪辑工具版本为准；导入不顺利时按配音重新识别字幕并校对。当前没有剪映草稿写入或 FFmpeg 渲染代码。

验收：完整观看，检查黑屏、断音、字幕越界、角色变化和转场。分辨率、帧率、码率等以发布时平台规范为准。

## 7. 发布与复盘

完成 `release_checklist.md`，在平台官方客户端人工上传。按发布当时的规则核对 AI 标识和素材使用要求。

每条记录作品链接、时间、生成费用、重试次数、人工分钟数、可获得的观看指标和评论反馈。首条样片用于找瓶颈，不用单条播放量预测长期收益。

## 本地工作目录约定

| 位置 | 内容 |
| --- | --- |
| `workspaces/episode-001/episode.json` | 源剧本 |
| `workspaces/episode-001/references/` | 批准的角色参考与授权记录 |
| `output/episode-001-v1/` | 当前模块生成的 8 个文件 |
| `output/episode-001-v1/images/` | 后续镜头图片 |
| `output/episode-001-v1/audio/` | 后续配音和背景声音 |
| `output/episode-001-v1/video/` | 后续剪辑导出成片 |

保存 JSON 的版本并备份重要素材；当前工具不提供云端备份或项目恢复。
